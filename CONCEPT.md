# Моя концепция почасовой витрины

26.10.2026, учебный мини-проект 0.1.0. Я хочу показать путь от небольших CSV
энергопотребления к объяснимому аналитическому результату за 5–10 минут.
Выбор идеи и разумного объёма делаю самостоятельно, ежедневную анкету не повторяю.

## Что я считаю строкой

| Поле | Контракт |
| --- | --- |
| event_id | Глобальный ID неизменяемого события, 1–64 ASCII letters/digits/_/-; первый символ alphanumeric |
| site_id, meter_id | Такие же синтетические ID; это не имена людей и не адреса |
| occurred_at | Точный формат YYYY-MM-DDTHH:MM:SSZ, UTC, годы 2000…2099, календарная дата существует |
| energy_wh | Потребление интервала, целое от 0 до 1000000000 без leading zero, знака и дроби |

Я принимаю UTF-8 без BOM/NUL, ровно пять полей в указанном порядке, стандартный
CSV с запятой/двойной кавычкой. Ограничиваю 10 MiB/100000 data records; пустую партию
отклоняю. Не выполняю autodetect типов: сначала VARCHAR, затем явная проверка/CAST.
Wh — величина за интервал, не накопительное показание счётчика и не мощность W.

## Какую идентичность я сохраняю

Batch ID = SHA256(version prefix + frozen file bytes); имя и путь файла не участвуют.
Повтор равных байтов — noop. Разные CSV могут доставить один event: равный typed
payload игнорирую при вставке, отличный payload того же event_id — whole-package
EVENT_CONFLICT. Новые факты и ingest ledger публикую одним COMMIT. Не обновляю
и не удаляю canonical facts через CLI. После неопределённого COMMIT повторяю тот же
CSV; исходные файлы нужно сохранять отдельно, встроенного raw archive здесь нет.

## Выход и критерии

Зерно hourly_usage — site_id/hour_utc. Я считаю event_count, meter_count,
energy_wh и day_cumulative_wh с явным оконным ROWS frame внутри UTC-дня площадки.
Поздний факт виден в старом bucket после COMMIT: это view, не mutable stored mart.
Parquet — отдельный законченный snapshot, который последующий приём не обновляет.
Export публикует новый файл без overwrite через same-filesystem hard link.

Я считаю первую версию законченной, когда воспроизводятся 840→910 Wh, повтор не
дублирует, конфликт с новым E007 не даёт частичной записи, UTC-день обнуляет окно,
чужая БД отклоняется, Parquet читается обратно и исходники упакованы по allowlist.
Факты проверок/CI/релиза отдельно фиксирую в VALIDATION.

## Что я оставляю за границей

Я не делаю IoT gateway, HTTP, очереди, тарифы/деньги, timezone бизнеса, SCD mapping,
автоматическое исправление событий, RBAC и распределённую загрузку. CLI report
считывает весь небольшой часовой результат; на большом объёме нужны фильтры/пагинация.
Область доверия — локальный владелец каталога без враждебного изменения родителей
во время команды. Multi-process writers, power loss и сетевые filesystem не проверены.
